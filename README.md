# LLMAgent

## Установка и запуск

Нужен Python **3.10 или новее**. Команды для Windows PowerShell:

```powershell
git clone https://github.com/anewmur/LLMAgent.git
cd LLMAgent
python -m venv .venv
.venv\Scripts\activate
pip install -e ".[dev]"
```

Зависимости заданы только в `pyproject.toml`; группа `dev` добавляет pytest.
Шаблоны, шрифт, `config/requirements.yaml` и системный промпт входят в пакет и берутся рядом
с установленным кодом (`config/paths.py`: `PACKAGE_ROOT`).

Можно собрать и поставить wheel:

```powershell
pip install build
python -m build
pip install dist\llmagent-0.1.0-py3-none-any.whl
```

Входные данные, ключ и результаты ищутся в папке запуска (`config/paths.py`: `PROJECT_ROOT = Path.cwd()`).
Поэтому `llmagent` и `python main.py` запускайте из папки, где лежат `input/` и `api_keys.env`;
комплект появится в `output/` этой же папки.

Скопируйте пример настроек и впишите свой ключ в `api_keys.env`:

```powershell
copy api_keys.env.example api_keys.env
```

Либо задайте ключ переменной окружения в текущем окне PowerShell:

```powershell
$env:DEEPSEEK_API_KEY="ваш_ключ"
```

Запуск и тесты:

```powershell
llmagent
# Альтернативный запуск: python main.py
pytest
```

Другую трассу можно передать аргументом: `llmagent input/examples/alternate.json`.
Если файла нет, программа пишет «Файл не найден: …» и завершается с кодом 1.
Без ключа программа выводит подсказку и завершается с кодом 1.
Выпуски создаются в `output/`. Папка не исключена из Git: по ТЗ сформированный комплект сдаётся вместе с репозиторием.

Примеры входных данных в `input/examples/`:
- `alternate.json` — другая трасса, 250 м;
- `no_p3.json` — нет отметки оси трубы в P3 (сценарий 3 ТЗ);
- `material_conflict.json` — в описании объекта «Сталь», у трубы «ПЭ 100» (сценарий 4 ТЗ);
- `gost_b1.json` — профиль по рисунку В.1 ГОСТ 21.704;
- `thick.json`, `thick_plan.json`, `thick_short.json` — крупные диаметры, труба двумя линиями.

Таблица «требование → пункт стандарта → где реализовано → способ проверки» и учтённые редакции стандартов —
`docs/requirements_table.md`. Архитектура и роль LLM — `docs/architecture.md`.

## Диалог и состояние трассы

Запуск: `python main.py`. Необязательный аргумент — другой входной файл, например
`python main.py input/examples/alternate.json`. При старте `RouteSession` один раз читает выбранный JSON
(по умолчанию `input/input.json`)
и выпускает начальный комплект прямо в `output/`. История изменений начинается пустой.
Исходный JSON не меняется; следующий запуск снова использует его данные.

Вопросы вводите по одной строке: при вставке нескольких строк консоль передаёт каждую строку агенту как отдельный вопрос, и ответы печатаются подряд без ожидания ввода.

Для переключения в диалоге используется `load_route(path)`, например
`load_route("input/examples/alternate.json")`. Путь должен быть относительным папке запуска и вести
в папку `input`. Разобранная трасса становится текущей; изменения и размер шрифта сбрасываются,
журнал вопросов продолжается. Если выпуск заблокирован, ошибки возвращаются агенту, а недостающие
данные новой трассы можно дописать через `update_point`. Прежняя трасса сохраняется при ошибке пути,
чтения или разбора проекта.

Все инструменты работают с текущим проектом в памяти. `update_point` принимает имя точки
и изменяемые `x`, `y`, `ground`, `axis`, где `ground` — отметка земли, `axis` — отметка оси трубы, в метрах.
Непереданные поля прежние; явный `null` означает попытку удалить значение.
Новые данные проверяются целиком. При ошибке проверки новых данных проект и история остаются прежними, инструмент возвращает причину, а модель задаёт уточняющий вопрос.
Материалы этим инструментом не редактируются; их конфликт выявляет проверка проекта.

Успешная правка сразу перевыпускает комплект и добавляет запись в `changes.md`.
Перечень содержит изменённые поля точки и общую длину трассы, если она изменилась.
В записи перечислены все четыре перевыпущенных листа. При нескольких правках записи идут по порядку.
Без изменений `changes.md` не создаётся. Начальный успешный выпуск новой сессии удаляет
прежний перечень. При выходе сохраняется журнал вызовов; перечень изменений уже записан при выпуске.

`session.tool_log` хранит номер вопроса, имя, аргументы и результат каждого вызова, а также предупреждения.
Краткая строка вызова печатается в консоль. Журнал сохраняется в `output/tool_log.md` через
`templates/tool_log.md` после каждого вопроса и при выходе, включая EOF/Ctrl+C.
При старте файл журнала создаётся заново; вопросы нумеруются с 1. История разговора остаётся в `messages`.

После каждого вопроса журнал показывает время обработки (включая инструменты), входные токены
с выделением попаданий в кэш, выходные токены и оценку стоимости API в USD.
В файле журнала сохраняются итоги вопросов и сумма за сеанс; время ожидания ввода не учитывается.
Цены заданы в `agent/settings.py`: тарифы deepseek-flash, проверенные 09.11.2026
по [официальной странице](https://api-docs.deepseek.com/quick_start/pricing/).
Тариф выбирается по времени ответа API: пик UTC 01:00–04:00 и 06:00–10:00 по будням; китайские праздники не учитываются.
Стоимость накапливается для каждого ответа; итоги вопросов находятся в отдельном `usage_log`.
Числа выводятся с десятичной запятой, стоимость — с шестью знаками. Расчёт без модели токены API не расходует.

Пример `input/examples/alternate.json`: 50 + 70 + 50 + 80 = 250 м, один отвод 90°.

## Выпуск без LLM

`python main.py` при старте создаёт комплект по исходному файлу прямо в `output/` без обращения к модели.
Ключ всё равно нужен: без него программа завершается до выпуска.
Пути задаются в `main.py`: `INPUT_PATH`, `OUTPUT_DIR` и `CONFIG_PATH`.
Системный промпт — в `agent/system_prompt.md`, модель и предел раундов — в `agent/settings.py`.
Конфиг читается один раз функцией `load_config()` в `main.py` и передаётся в сессию и выпуск.
В Python можно использовать `RouteSession(INPUT_PATH, OUTPUT_DIR, config).release()`; для правки —
`session.update_point("P5", x=300)`. Генератор `create_package(project, output_dir, config)` принимает
готовый проверенный `Project`; сохранение данных в промежуточный JSON не требуется.

Состав: `general.svg`, `plan.svg`, `profile.svg`, `specification.svg`, `specification.csv`,
`check_report.md`, `tool_log.md`; в `pdf/` — только `package.pdf` со всеми четырьмя листами.
После успешных правок добавляется `changes.md`. Допущения и ограничения — разделы `check_report.md`.
Сценарных каталогов, снимков входа и манифеста нет. Сборка и проверки выполняются во временной папке;
`output/` заменяется новым комплектом только после успешных проверок.
- Если не выпускается текущий проект (старт, `release_documents`, `load_route`, принятое удаление отметки оси),
  `output/` очищается и в нём остаётся только отчёт об отказе `check_report.md` («Комплект не выпущен»).
- Если отклонена правка (`update_point`, `update_pipe`, `add_point`, `change_profile_font` и др.), проект и
  `output/` не меняются: остаётся последний выпущенный комплект.

Журнал сохраняется после завершения вопроса независимо от результата выпуска.
Для перевыпуска без правки точки агент вызывает `release_documents`.

Конфигурация `config/requirements.yaml` содержит состав документов, нормативные ссылки,
допущения в виде `{id, full, short, key}` и ограничения. `load_assumptions(config, project, vertical_scale, plan_scale)`
подставляет значения проекта: отчёт получает все `full`, лист общих данных и агент —
только `short` с флагом `key: true`. Порядок записей берётся из YAML.
Подсчёт листов СО отделён от НВ. Перечень требований в
`docs/requirements.md` — справочный текст. Нормативные основания: `docs/normative_basis.md`.

Во всём комплекте используется DejaVu Sans из assets/fonts с лицензией; шрифт встраивается в PDF.
Все подписи плана используют единый DejaVu Sans, поддерживающий знак ⌀; шрифты встраиваются в PDF.

## Продольный профиль (шаги 7.8–7.10)

`ProfileDrawing(project, document, config).render()` возвращает SVG профиля на A3; файлы создаёт общий выпуск комплекта.
Горизонтальный масштаб выбирается автоматически: крупнейший из ряда 1:1000, 1:2000, 1:5000
(`config/drawing_settings.py`: `PROFILE_HORIZONTAL_SCALES`), при котором вся длина помещается в поле;
вертикальный — 1:100. Оба можно задать параметрами `horizontal_scale` и `vertical_scale`. Пикетаж — накопленная длина,
низ трубы и глубины — из расчёта уровней. Шаблон сетки формы 2 находится в
`templates/profile_grid.svg`: отметки, труба, основание, уклоны и длины, расстояния,
номера точек и дополнительная строка пикетажа. Глубины стоят над профилем.
Пропущенные отметки не интерполируются, неизвестные значения — прочерк.
Если профиль не помещается по ширине ни при одном масштабе ряда, выпуск отклоняется. Выход графика
и подписей за поле по высоте даёт предупреждение. Интервалы точек менее 8 мм дают предупреждение
о тесных подписях; расположение элементов автоматически не исправляется.
Диаметр менее 2 мм в вертикальном масштабе изображается одной линией по низу трубы,
от 2 мм — двумя контурами. В строке уклонов диагональ показывает направление;
число над ней — уклон, под ней — длина. Прямые разделители отделяют участки.
Базовый шрифт по умолчанию 3,5 мм; `session.change_profile_font` меняет его на одну
ступень ряда и перевыпускает комплект. Названия — в 1,5–2 раза крупнее базового.
Подписи профиля используют тот же DejaVu Sans из настроек, что и подписи плана.
Если шрифт не помещается в фиксированные строки, инструмент возвращает ошибку.

## План трассы (шаги 7.5–7.7)

`PlanDrawing(project, document).render()` возвращает SVG плана без записи файлов.
План выпускается через сессию и общий генератор: геометрия трассы, имена точек, длины участков
и пикеты на A3. Подписи берутся из расчёта; длины и пикеты округляются только при выводе.
Масштаб плана выбирается автоматически (`core/drawing_scale.py`: `choose_plan_scale`): крупнейший из ряда
1:500, 1:1000, 1:2000, 1:5000 (`config/drawing_settings.py`: `PLAN_SCALES`), при котором трасса помещается в поле листа
по ширине и высоте. Тот же механизм `choose_scale` выбирает горизонтальный масштаб профиля.
Примеры: основная трасса — 1:1000; P5 на X = 400 м — 1:2000; `alternate.json` — 1:500.
Масштаб показан в штампе после названия листа: «План сетей водоснабжения (1:N)».
Если трасса или блоки подписей не помещаются даже при 1:5000, выпуск отклоняется с сообщением
«План с подписями не помещается на A3 даже при масштабе 1:5000…». При правке прежний комплект сохраняется.
Масштаб можно задать явно параметром `scale`. Формат листа автоматически не выбирается.
Размеры поля, отступы, линии, шрифты плана и перенос названия листа заданы в `config/drawing_settings.py`.
Проектируемый подземный водопровод показан штриховой толстой линией.
Вершины отмечены белыми кружками; имя, пикет и координаты собраны в один блок.
У отводов стоят номера УП по порядку трассы;
значения углов, отличных от 90°, выводятся в градусах и минутах.
Подпись трубы берётся из входа; обозначение сети В1 — принятое допущение PC-06.
Постоянная легенда хранится в `templates/plan_legend.svg` слева от основной надписи.
Габариты подписей оцениваются по размеру шрифта. Если блок подписей точки налезает на другую подпись
или на трубу, он сдвигается вверх или вниз и соединяется с точкой выноской. Оставшиеся пересечения
попадают в отчёт как предупреждения; комплект выпускается со статусом `warning`.
Сессия принимает изменение и передаёт предупреждения агенту.
Несоответствие угла отвода координатам блокирует выпуск плана.
PDF здесь не создаётся.

## Спецификация (шаг 7.4)

`SpecificationDrawing(project, document).render()` возвращает SVG спецификации по проверенному проекту.
Метод `write_csv(path)` записывает CSV (UTF-8 с BOM, разделитель `;`).
Выпуск использует общий `save_drawing`, как для плана и профиля.
Формат — A3, форма 1 ГОСТ 21.110-2013.

В `templates/specification.svg` находится только макет таблицы.
Рамка и штамп берутся из общего класса `Sheet` и `templates/sheet.svg`.
Заголовки, вертикальная сетка и текст строк используют ширины граф из `WIDTHS`.
Высоты строк формируются по данным. Название и нумерацию в штампе задаёт выпуск
через `drawing.sheet`; по умолчанию у однолистовой спецификации номер пустой, «Листов» — 1.

Количества берутся из расчёта. Неизвестные стандарт/ТУ, код продукции,
поставщик и масса остаются пустыми. Недостающие сведения будут отражены в отчёте на шаге 7.12.
Поле `pipe.standard` необязательное: если заполнено во входном JSON, выводится
в графе «Тип, марка, обозначение документа, опросного листа» у трубы.
Материал и SDR отвода приняты как у трубы; это допущение указано в примечании.
Высота заголовка — 32 мм, строк — от 8 мм с увеличением при переносах.
Если таблица не помещается на один лист, выпуск останавливается с сообщением:
многостраничный вариант пока не реализован.
Отклонение от рисунка формы 1: таблица начинается на 25 мм ниже верхней рамки
для размещения надписи «УЧЕБНЫЙ КОМПЛЕКТ». Это ограничение для отчёта 7.12.

## Пробный лист A3 (шаги 7.2–7.3)

Класс `Sheet` заполняет реквизиты в общем макете `templates/sheet.svg`.
Все четыре листа используют один A3 альбомный 420×297 мм и один шаблон `sheet.svg`.
Параметра формата нет. Основная надпись — 185×55 мм; рамка и штамп заданы в SVG.
Вызов: `Sheet(designation, object_name, title, total=total).render()`; номер листа выставляется отдельно из состава документов.
Рамка, сетка основной надписи и постоянные подписи находятся в SVG;
Python подставляет реквизиты и переносит длинное название листа.

Основной комплект находится прямо в `output/`; отдельные пробные листы и превью — в `tmp/`.
Из Git исключён только `tmp/`. Тесты используют `tempfile` и `tmp_path`.

Создать лист в Python: `Sheet(designation, object_name, title, total=total).render()`.

Для выпуска файлов используйте `python main.py` или обычный вызов `create_package(project, output_dir, config)`.

## Как устроена задача (пояснение для проверяющего)

- Комплект НВ по ТЗ разд. 3: общие данные, план трассы, продольный профиль. Спецификация (обозначение .СО) прилагается к комплекту и записывается в ведомость ссылочных и прилагаемых документов (ГОСТ 21.110 п. 4.13). Отчёт о проверках — документ ТЗ, в комплект по ГОСТ не входит.
- Сеть состоит из участков. Участок — прямой отрезок между двумя соседними точками трассы (P0–P5). В точках поворота установлены отводы.
- План и профиль изображают одну и ту же трассу: длины, расстояния и номера точек на них совпадают.
- Количество трубы в спецификации (м) равно сумме длин участков и вычисляется программой.
- Каждый лист имеет основную надпись с обозначением документа.
- Изменение входных данных (например, перенос P5) ведёт к перевыпуску всех связанных документов (ГОСТ Р 21.101 п. 7.1.4).

## Основные понятия

- **Сеть (система) В…** — Наружная сеть водоснабжения с буквенно-цифровым обозначением (например, В1, В2) по ГОСТ 21.205.
- **Участок трубопровода** — Прямолинейный отрезок сети между двумя точками трассы. Свойства: длина, уклон, диаметр, отметки концов.
- **Точка трассы** — Характерная точка (P0–P5): начало и конец, точка разрыва или присоединения (марка Т), угол поворота (марка УП). Свойства: координаты, отметки.
- **Угол поворота (УП)** — Точка изменения направления трассы. Значение в градусах; на плане не подписывают, если угол 90°.
- **Труба / материал** — Изделие с наружным диаметром и толщиной стенки (⌀110×6,6), материалом ПЭ 100 SDR 17 и документом-стандартом.
- **Фасонная часть (отвод)** — Элемент трубопровода (отвод). УГО по 21.206 табл. 1; включается в спецификацию (PC-03).
- **Основной комплект НВ** — Основной комплект рабочих чертежей марки НВ (наружные сети водоснабжения).
- **Общие данные** — Первые листы комплекта: ведомости, условные обозначения, общие указания.
- **План сетей** — Чертёж трассы в плане (подосновы нет — см. limitations).
- **Продольный профиль** — Развёртка по оси трубопровода с поверхностью земли, трубой и сооружениями.
- **Сетка (таблица) профиля** — Таблица под профилем, боковик по форме 2 (подземная прокладка).
- **Спецификация СО** — Прилагаемый текстовый документ по форме 1 ГОСТ 21.110 с шифром «СО».
- **Позиция спецификации** — Строка спецификации: поз., наименование и техническая характеристика, тип/марка/документ, код, поставщик, ед. изм., кол., масса, примечание.
- **Лист** — Единица графического или текстового документа с основной надписью, форматом по ГОСТ 2.301 и номером.
- **Основная надпись** — Штамп листа (формы 3, 6) с графами: обозначение, наименования, стадия, лист/листов, формат.
- **Обозначение документа** — Базовое обозначение + «-НВ» (комплект), «.СО» (спецификация).
- **Ведомость** — Ведомость рабочих чертежей (форма 1), ведомость ссылочных и прилагаемых документов (форма 2).


## Добавление и удаление точек и отводов

- `add_point(name, after, x, y, ground, axis, bend_angle=None)` вставляет точку после `after`.
- `remove_point(name)` удаляет точку вместе с отводом в ней; должно остаться минимум две точки.
- `add_bend(at, angle_deg)` добавляет отвод в существующей точке.
- `remove_bend(at)` удаляет отвод в точке.

Все операции проверяются и выпускаются через общую транзакцию. Поворот без отвода блокирует правку.
При отклонённой вставке точка не появляется в трассе. После согласия пользователя агент повторяет
`add_point` с углом из проверки. Для переноса существующей точки в том же вызове `update_point`
передаётся список `bends` вида `[{"at": "P4", "angle_deg": 14.04}]` со всеми отводами из сообщений проверки:
новые отводы добавляются, углы существующих заменяются, всё применяется одной транзакцией вместе с переносом. Имена остальных точек сохраняются.
Угол `0` в `bends` удаляет отвод в той же правке: например, вернуть трассу прямой можно вызовом
`update_point("P5", y=80, bends=[{"at": "P4", "angle_deg": 0}])`.
В перечень изменений входят координаты, отметки, углы и изменение общей длины; пропущенное значение выводится как «—».

## Ограничения

Полный список — раздел «Ограничения» в `output/check_report.md` (источник — `limitations` в `config/requirements.yaml`). Главное:
- нет колодцев, камер, футляров и пересечений с другими сетями и дорогами;
- нет геологии, грунтовых вод, натурной поверхности земли и основания — они не выдумываются;
- у точки одна отметка оси трубы: перепад отметок на одной вертикали (два значения в одном пикете) не поддерживается,
  совпадающие соседние точки дают ошибку «длина участка в плане равна нулю»;
- нет гидравлики, прочности, расходов и напоров; таблица основных показателей сети не заполняется;
- формат листа только A3, спецификация только на одном листе; DXF и схема напорной сети не выпускаются;
- автоматически устраняются не все наложения подписей — новый вход нужно смотреть глазами.

## Что улучшить

Автоматически предлагать подходящий отвод без повторного вызова отклонённой операции.


## Изображение трубы и отводов

Общий выбор `pipe_line_count` следует ГОСТ 21.206-2012, п. 3.5: от 2 мм наружного
диаметра в масштабе вида используются два контура. На плане они сплошные толстые,
с отступами ±D/2; ось включается `DRAW_PIPE_AXIS`. В одну линию сохраняются штрихи и углы.
Полка общая для плана и профиля: обозначение сети сверху, наружный диаметр и стенка снизу.
Материал и SDR остаются в спецификации и примечаниях. На профиле полка нужна при двух контурах;
отводы плана на развёртку не переносятся.

Радиус отвода по оси принят как `BEND_RADIUS_FACTOR × D` — учебное допущение.
Если касательная дуги превышает половину соседнего участка, выпуск даёт предупреждение,
а этот стык показывается углом. Радиус автоматически не уменьшается.
Пример двухлинейного плана: `input/examples/thick_plan.json` (2200×130 мм, SDR 17).
